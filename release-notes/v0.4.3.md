# Wsh 0.4.3

Fixes history saving stopping for every shell after a shell is killed while saving, for example when a terminal multiplexer restarts. Every prompt reported `locking failed for ~/.zsh_history: file exists` and no history was saved until the leftover `~/.zsh_history.LOCK` was deleted by hand. Wsh now removes a leftover lock once it is more than 10 seconds old, as Zsh 5.9 does.

## Changes

- History saving recovers on its own after a shell dies mid-save, and a shell that exits while another shell is briefly saving now waits for it instead of losing the history it saves on exit. Unread mail in `$MAIL` is announced once after delivery instead of at every mail check. Both problems came from the pinned Zsh revision comparing file times with a clock that counts from boot. The [upstream bug record](https://github.com/wakamex/wsh/blob/v0.4.3/UPSTREAM-ZSH-BUGS.md#monotonic-clock-compared-with-file-times) has reproducers, and the history fix is also submitted to Zsh as [zsh-workers 55194](https://zsh.org/workers/55194). Real-terminal tests cover leftover and in-use history locks and mail notices. ([db3caee](https://github.com/wakamex/wsh/commit/db3caee))
- The daily plugin upstream check now treats plugin files that Wsh already recognizes as known, even when they come from a different repository than the catalog entry. ([f7487b1](https://github.com/wakamex/wsh/commit/f7487b1))
- Name the attest action's pinned commit correctly. ([d9fae73](https://github.com/wakamex/wsh/commit/d9fae73))

## Installation and upgrade

Existing COPR installations can update with `sudo dnf upgrade --refresh wsh`. Shells started before the upgrade keep the old behavior until they are restarted. If a leftover lock is blocking history right now, `rm ~/.zsh_history.LOCK` clears it immediately.

## Verification

The history and mail fixes passed the installed Wsh suite and upstream Zsh tests. In daily use on a [Wakterm](https://github.com/wakamex/wakterm) host, restarting the terminal multiplexer left no history lock behind, and each pane's Up recall still showed that pane's own commands first.
