# Wsh 0.4.7

An interactive Wsh session now works without [Oh My Zsh](https://ohmyz.sh/) or any `.zshrc`: Wsh sets up completion, the usual editing keys and history clean-up itself, and anything you set in `.zshrc` still wins. Each pane's commands reach shared history as they run, the Git prompt stays fast in repositories whose files were touched without changing, and terminals that restore panes through `wsh --run` see the right working directory.

## Changes

- Interactive defaults: Home, End, Delete, Ctrl+Left and Ctrl+Right, Ctrl+Delete, Page Up and Page Down, Shift+Tab in the completion menu and Ctrl+X Ctrl+E work in the emacs and vi keymaps; Tab opens a completion menu with case-insensitive matching; duplicate and space-prefixed commands stay out of history; `#` starts a comment at the prompt; Ctrl+S no longer freezes the terminal; word motions stop at `/` and `-`; and in-memory history holds 50,000 entries. Wsh applies these before your startup files, so your own settings replace them. [NATIVE-INSTALLATION.md](https://github.com/wakamex/wsh/blob/v0.4.7/NATIVE-INSTALLATION.md#interactive-defaults) lists them all. ([8a162b5](https://github.com/wakamex/wsh/commit/8a162b5))
- Completion: when your startup files do not run `compinit`, Wsh does after them and applies any `compdef` calls they made. If you or Oh My Zsh already set it up, Wsh leaves that alone, and `WSH_DISABLE_COMPLETION=1` turns it off. A shell with an empty `.zshrc` now starts in about 34 ms instead of 19 ms because it has completion, the same cost as running `compinit` yourself; other startups are unchanged. ([8a162b5](https://github.com/wakamex/wsh/commit/8a162b5), [measurement](https://github.com/wakamex/wsh/blob/v0.4.7/benchmarks/interactive-defaults-2026-10-12/report.md))
- Removing Oh My Zsh from a `.zshrc` now changes only the behavior [FEATURES.md](https://github.com/wakamex/wsh/blob/v0.4.7/FEATURES.md#defaults-replacing-oh-my-zsh) leaves to your own files, such as `auto_cd` and the `l`/`la`/`ll` aliases, or does not adopt. A test compares the two setups. ([d43d042](https://github.com/wakamex/wsh/commit/d43d042), [5c4e660](https://github.com/wakamex/wsh/commit/5c4e660), [f5e86bc](https://github.com/wakamex/wsh/commit/f5e86bc))
- Pane history: each command reaches the shared history file as it runs, so a new shell sees commands from shells that are still open, while Up keeps recalling the pane's own commands first. Live sharing between open shells (`share_history`) is off unless you set it yourself; Wsh turns off the copy Oh My Zsh enables. ([02c1de2](https://github.com/wakamex/wsh/commit/02c1de2))
- With live sharing on, Up and Down history search now skips commands from other shells after you switch to local history with `set-local-history`, as Zsh's own history movement does. ([6df2c1e](https://github.com/wakamex/wsh/commit/6df2c1e))
- Git prompt: in a repository whose files were touched without changing, for example by a build or checkout, the built-in prompts rechecked every file at each prompt. After a status that takes 100 ms or more, Wsh now refreshes the index once in the background, so later prompts are fast again; in a 20,000-file test repository the first prompt took 230 ms and later ones 17 ms. The refresh never runs while `index.lock` exists or during a rebase, merge, cherry-pick, revert or bisect. It works around Git creating `index.lock` on every status that may take locks, which a [proposed Git fix](https://lore.kernel.org/git/20261022184420.3648771-1-mcosma@gmail.com/) addresses. ([86079eb](https://github.com/wakamex/wsh/commit/86079eb), [3975e1a](https://github.com/wakamex/wsh/commit/3975e1a), [7b9b51a](https://github.com/wakamex/wsh/commit/7b9b51a))
- Directory reporting: a `cd` inside a subshell, such as `(cd /somewhere && tool &!)` in a startup file, told the terminal the shell had moved. `wsh --run` panes kept that wrong directory for as long as their command ran, so terminals opened new splits there. Wsh no longer reports a subshell's directory, and `wsh --run` reports the command's directory before it starts. ([ad39909](https://github.com/wakamex/wsh/commit/ad39909))
- zsh-syntax-highlighting at upstream commit e6683f2 is recognized, so Wsh's faster highlighter takes over from it as it does for the pinned version. ([368e4af](https://github.com/wakamex/wsh/commit/368e4af))

## Installation and upgrade

Fedora 44 x86-64 users with the [COPR repository](https://copr.fedorainfracloud.org/coprs/wakamex/wsh/) enabled can update with `sudo dnf upgrade --refresh wsh`. Shells started before the upgrade keep the previous behavior until they are restarted, including panes restored through `wsh --run`.
