# Wsh 0.4.1

History now persists across logins by default. In Wakterm panes with a stable pane token, Up recalls that pane's commands first, followed by shared history; commands merge into shared history when the shell exits.

- Fresh configurations retain up to 10,000 history entries without importing other active sessions' commands. Explicit history settings remain respected. See [history configuration](../NATIVE-INSTALLATION.md#history).
- Pane history recovers pending commands after a killed shell or an `exec`, keeps nested shells from claiming the same pane, and coordinates with Wakterm's shell integration. See [pane-history behavior and tests](../benchmarks/pane-history-2026-09-26/report.md).
- Fedora 44 x86-64 users can install and update through the signed [COPR repository](https://copr.fedorainfracloud.org/coprs/wakamex/wsh/). COPR publications now advance the Wsh patch version, with RPM release reset to `1`.
- Packages use `/usr/bin/wsh` and Fedora's standard shell registration and removal behavior. When upgrading from the original v0.4.0 GitHub RPM, restart existing Wsh sessions to pick up the new resource paths. Before uninstalling, switch accounts using Wsh to another installed shell and verify login. See the [packaging review](../packaging/FEDORA-REVIEW.md).

The history implementation passed upstream, installed and PTY suites, including signed-package upgrade, login, job control, reboot and removal qualification in COPR `0.4.0-2`. Version `0.4.1` carries the same implementation under the new version policy. A real Wakterm mux-restart qualification remains outstanding.
