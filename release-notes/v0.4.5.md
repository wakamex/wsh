# Wsh 0.4.5

Recognizes every [zsh-z](https://github.com/agkozak/zsh-z) version Oh My Zsh has bundled since October 2022, so older copies of its `z` plugin run on Wsh's native directory jumping. Copies kept inside dotfiles repositories rarely update, and the older versions lose your whole directory history when `z -xR` is given a missing path, never raise the rank of directories whose paths contain `$`, `[ ]` or a backtick, and create the database readable by other users. Wsh's implementation has none of these problems.

It also fixes Ctrl-C at the prompt. On a busy machine, about 1 to 4% of presses in 0.4.4 left the line in place and the shell waiting for another key instead of starting a fresh prompt, and a rarer case left the shell ignoring all input until it was restarted.

## Changes

- Wsh now catalogs the eight Oh My Zsh `z` versions from October 2022 through May 2026, in addition to the two it already recognized. Versions before August 2026 lack two helper functions that newer ones define, and the handoff now checks those helpers only when they exist. ([45e67cc](https://github.com/wakamex/wsh/commit/45e67cc))
- Plugin recognition looks up cataloged files by size, so startup compares bytes only against a reference of the same size. An unrecognized or edited plugin file now costs one file-size check, and recognizing a plugin with many cataloged versions takes about half as long. ([1194f45](https://github.com/wakamex/wsh/commit/1194f45))
- Ctrl-C at the prompt always discards the line. An interrupt that arrived while syntax highlighting or autosuggestions were running, or just before the shell waited for input, could be lost, so the shell kept waiting for the next key. An interrupt that arrived as a loop was ending could also leave the shell skipping every later command. Wsh's Zsh build carries three fixes for these, recorded as upstream bugs, and Wsh's own highlighting and history code no longer clears a pending interrupt. In a test that presses Ctrl-C during a pending autosuggestion on a machine with every CPU busy, 800 of 800 runs returned a fresh prompt. ([6f0eef2](https://github.com/wakamex/wsh/commit/6f0eef2), [707c528](https://github.com/wakamex/wsh/commit/707c528), [668767f](https://github.com/wakamex/wsh/commit/668767f), [55f95ea](https://github.com/wakamex/wsh/commit/55f95ea))
- Two Zsh tests that failed intermittently on busy machines are fixed: a terminal-query test no longer captures its own typed `exit`, and the zpty duplication test waits for each reply instead of racing its child. The fixes change only the tests. ([db6e3cf](https://github.com/wakamex/wsh/commit/db6e3cf), [20116d6](https://github.com/wakamex/wsh/commit/20116d6))
- Record the 0.4.4 publication. ([e86cb54](https://github.com/wakamex/wsh/commit/e86cb54))

## Installation and upgrade

Fedora 44 x86-64 users with the [COPR repository](https://copr.fedorainfracloud.org/coprs/wakamex/wsh/) enabled can update with `sudo dnf upgrade --refresh wsh`. Shells started before the upgrade keep the previous catalog until they are restarted.
