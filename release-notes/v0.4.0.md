# Wsh v0.4.0

Wsh v0.4.0 brings faster editing, history search, directory jumping and completion startup, plus a system-installed shell that can start without private Wsh setup. Existing Zsh configuration, Oh My Zsh, completion functions and job control remain supported.

## Faster everyday use

The comparisons measure complete editing, command or prompt workloads against the tested Zsh plugins and themes.

| Workload | Measured improvement | Baseline and evidence |
| --- | --- | --- |
| Syntax highlighting | 35–91% shorter complete redraw time across four workloads | Original Zsh main highlighter; [installed results](https://github.com/wakamex/wsh/blob/74105b9/benchmarks/native-highlighting-installed-2026-09-10/report.md) |
| Autosuggestions with 10,000 history entries | 29% less editing time: 7.294 to 5.160 ms median | Pinned Zsh autosuggestions plugin; [installed results](https://github.com/wakamex/wsh/blob/74105b9/benchmarks/native-autosuggestions-installed-2026-09-10/report.md) |
| History substring search with 10,000 entries | 23% less editing time in default mode; 72% less with uniqueness enabled | Pinned history-search plugin, 11.032 to 8.526 ms and 238.097 to 65.840 ms median; [installed results](https://github.com/wakamex/wsh/blob/74105b9/benchmarks/native-adoption-2026-09-10/history/report.md) |
| Directory jumping with 1,000 saved directories | 84% shorter lookup time: 52.542 to 8.540 ms median | Pinned Zsh directory-jump implementation; [installed results](https://github.com/wakamex/wsh/blob/74105b9/benchmarks/native-directory-final-2026-09-10/installed-report.md) |
| Cold completion startup | 20% shorter startup time: 155.429 to 123.600 ms p95 | Original compinit registration; warm startup remains approximately 37.6–37.8 ms; [installed results](https://github.com/wakamex/wsh/blob/74105b9/benchmarks/native-adoption-2026-09-10/completion/report.md) |
| Wsh's Agnoster prompt | Up to 95% shorter prompt waits: about 3 ms versus 45–56 ms | OMZ Agnoster on matched repository workloads; [prompt comparison](https://github.com/wakamex/zsh-theme-bench/blob/e67ca009a4145eef02dc3def5afa59a1523d3b75/research/wsh-comparison-2026-09-12/report.md) |

The editing and directory comparisons use medians; cold completion uses p95. Component comparisons use 50 alternating pairs per workload after correctness checks; prompt comparisons use 50 alternating pairs per theme, repository size and state. These are separate qualified experiments, not additive improvements or a whole-release speedup. [Performance details](https://github.com/wakamex/wsh/blob/74105b9/PERFORMANCE.md) retain the methods, exact inputs and limitations.

Robbyrussell also receives fresh Git status about 9 ms sooner than the tested OMZ version; its input-readiness improvement is under 1 ms. Select Wsh's prompt with `WSH_THEME=agnoster wsh` or `WSH_THEME=robbyrussell wsh`. Selecting a theme through OMZ continues to use OMZ's implementation. Minimal, Wakamex and local theme definitions remain available. ([Theme selection](https://github.com/wakamex/wsh/blob/74105b9/THEMES.md))

## Installation and account login

Wsh starts directly as the shell executable. Missing or corrupt per-user activation state no longer prevents account login, and basic shell startup works without the optional prompt helper. Fedora packages register the supported shell paths in `/etc/shells`. Running shells retain their bundled modules across package replacement, and ordinary package removal refuses while a local account still names Wsh as its shell. ([Native startup](https://github.com/wakamex/wsh/commit/0f8bb8b), [module lifetime](https://github.com/wakamex/wsh/commit/aa4f0d2), [package qualification](https://github.com/wakamex/wsh/commit/ddb3efc))

System-package installation and login are qualified on x86-64 Fedora. Install, upgrade and downgrade selected RPMs through DNF; there is no hosted DNF repository. Source builds can run directly on Linux without RPM or Fedora when the required dependencies and libraries are available. A self-contained source-RPM recipe supports offline Fedora rebuilds using the distribution's compiler, libraries and debug-package tooling. ([Source-RPM qualification](https://github.com/wakamex/wsh/commit/a05e5d1), [installation guide](https://github.com/wakamex/wsh/blob/74105b9/NATIVE-INSTALLATION.md))

This is a clean distribution cutover for fresh installations. Package management replaces `wsh update` and the old bundle manager. Test the installed shell with your configuration before changing your account shell. The canonical binary build retains its glibc 2.28 floor; downstream source rebuilds have their own system-library requirements.

## Commands and configuration

| Task | Command |
| --- | --- |
| Inspect duplicate plugins and prompt ownership | `wsh --doctor` |
| Profile interactive startup | `wsh --profile -- -i` |
| Include function timings | `wsh --profile --functions -- -i` |
| Recover a saved profiling report | `wsh --profile-report DIRECTORY` |
| Run a program, then return to a prompt | `wsh --run -- PROGRAM ARG...` |
| Start that program in a login shell | `wsh --run --login -- PROGRAM ARG...` |
| Show compiled Wsh identity | `wsh --wsh-version` |
| List Wsh options | `wsh --wsh-help` |

Wsh tools use explicit options in the first argument position. Plain script names and arguments after `--` retain their Zsh meanings, and `wsh --version` reports Zsh's version. Foreground invocation preserves exact argument bytes, Ctrl-C, Ctrl-Z, `fg` and prompt return. ([Command options](https://github.com/wakamex/wsh/commit/ef13a1c), [foreground invocation](https://github.com/wakamex/wsh/commit/a98921b))

Your existing prompt remains the default. To use Zsh and Wsh interchangeably, leave the shared configuration intact and select a Wsh theme on the command line. Skipping OMZ's theme under Wsh is an optional optimization. Doctor suggests cleanup without editing configuration. ([Configuration choices](https://github.com/wakamex/wsh/commit/74105b9))

## Compatibility and reliability

- Supported unmodified plugin copies use Wsh's implementations, including recognized older versions. Matching uses a local catalog first, then bounded Git provenance for uncataloged upstream checkouts. Modified or unverified implementations remain external. New upstream features may temporarily be absent from Wsh; the tested uncataloged checkout added about 12 ms to median startup. Daily upstream monitoring flags changes for review. ([Recognition](https://github.com/wakamex/wsh/commit/4a94e99), [monitoring](https://github.com/wakamex/wsh/commit/b12185f))
- Wsh removes recognized OMZ `git-prompt` collector hooks when its own prompt is selected, avoiding duplicate collection while preserving unrelated customization. ([Prompt ownership](https://github.com/wakamex/wsh/commit/9a5c703))
- Directory jumping preserves existing data and settings, confirms whole-database deletion and supports updates to bind-mounted database files. ([Confirmation](https://github.com/wakamex/wsh/commit/aca3cf2), [file updates](https://github.com/wakamex/wsh/commit/b5425ff))
- Highlighting preserves styles, optional highlighters and redraw integration. Its qualification passed 287 upstream fixtures and 3,360 actual-style prefix comparisons. A bundled Zsh fix also prevents obsolete neutral highlighting regions from accumulating. ([Highlighting](https://github.com/wakamex/wsh/commit/f54df6f), [Zsh fix](https://github.com/wakamex/wsh/commit/ab1691c))
- Profiling captures early exits and interrupted startup, supports saved-report recovery and keeps child-shell tracing isolated. Default traces exclude command text, environment contents and user paths. ([Startup recovery](https://github.com/wakamex/wsh/commit/3fa3951), [isolation](https://github.com/wakamex/wsh/commit/5205c70))
- Completion keeps the user's compinit initialization, security checks, caches and existing functions. Automatic or deferred initialization is not enabled by this release. ([Scanner adoption](https://github.com/wakamex/wsh/commit/799e1d6))

## Build and validation

The build no longer requires Rust or Cargo. Wsh's native additions and prompt helper are C; Zsh still owns the language and editor, with selected configuration and lifecycle adapters remaining Zsh code. The complete helper comparison reduced executable size by about 78% and active collection threads from three to two while passing its latency gates. It did not establish a general latency advantage over Rust. ([Build consolidation](https://github.com/wakamex/wsh/commit/32d2bc6), [helper comparison](https://github.com/wakamex/wsh/blob/74105b9/benchmarks/native-render-2026-09-08/runtime-report.md))

Qualification includes upstream Zsh tests, installed editor and job-control checks, offline Fedora source builds, and QEMU PAM login, recovery and reboot with enforcing SELinux. Two independent canonical builds produced identical RPMs and installation manifests. The publication workflow verifies exact-commit eligibility and repeated builds, then publishes GitHub build provenance. Local development builds remain unsigned; the RPM has no separate maintainer GPG signature. ([Package evidence](https://github.com/wakamex/wsh/blob/74105b9/benchmarks/release-qualification-2026-09-10/report.md), [release contract](https://github.com/wakamex/wsh/blob/74105b9/RELEASES.md))
