# Wsh 0.4.2

Wsh now remembers commands across logins by default, recalls pane-specific history in Wakterm, and supports signed Fedora installation and updates through COPR. This GitHub release covers all changes since `v0.4.0`, including the changes shipped through COPR as `0.4.1`.

## Changes

- History persists by default in `~/.zsh_history`, with 10,000-entry limits for saved and in-memory history. Ordinary sessions append commands as they are entered without importing other active sessions' commands. Existing history settings can override these defaults. See [history configuration](https://github.com/wakamex/wsh/blob/v0.4.2/NATIVE-INSTALLATION.md#history) and the [implementation commit](https://github.com/wakamex/wsh/commit/0bbb22a).
- In Wakterm panes that supply a stable pane token, Up and history search recall that pane's commands first, with shared history behind them. New commands merge into shared history on exit; pending commands recover on the next same-pane start after an interrupted shell. Pane mode disables live sharing and supports an opt-out. See [pane history](https://github.com/wakamex/wsh/blob/v0.4.2/TERMINAL-INTEGRATION.md#pane-history-merges-on-exit) and the [implementation commit](https://github.com/wakamex/wsh/commit/3f15fec).
- Fedora 44 x86-64 users can install from the signed [COPR repository](https://copr.fedorainfracloud.org/coprs/wakamex/wsh/) and receive Wsh updates through DNF. Each COPR publication now advances the Wsh patch version. The [source RPM](https://github.com/wakamex/wsh/blob/v0.4.2/packaging/SOURCE-RPM.md) builds offline with Fedora's compiler flags, license metadata and bundled-dependency declarations.
- `wsh --doctor` now works from an interactive terminal instead of timing out after ten seconds. The `setsid --wait` workaround is no longer needed. The [fix](https://github.com/wakamex/wsh/commit/cbc8687) includes real-terminal tests for reporting, interruption, timeout and child cleanup.

## Installation and upgrade

For Fedora 44 x86-64:

```sh
sudo dnf copr enable wakamex/wsh
sudo dnf install wsh
```

Existing COPR installations can update with `sudo dnf upgrade --refresh wsh`. COPR `0.4.2` already contains these functional changes.

Packages now install the shell directly at `/usr/bin/wsh`, with its helper under `/usr/libexec/wsh` and data under `/usr/share/wsh`. After upgrading from the original `v0.4.0` GitHub RPM, restart existing Wsh sessions so they use the new resource paths. Before uninstalling, switch accounts using Wsh to another installed shell and verify login: removal now follows Fedora's shell-package behavior, removing shell registrations without changing account records or blocking the transaction. See the [packaging changes](https://github.com/wakamex/wsh/commit/9b1f538) and [installation guide](https://github.com/wakamex/wsh/blob/v0.4.2/NATIVE-INSTALLATION.md).

The history and doctor changes passed upstream Zsh and installed Wsh suites. Signed COPR packages passed DNF upgrade, fresh installation, real terminal tests, login/job control and removal/recovery checks. The [publication evidence](https://github.com/wakamex/wsh/blob/v0.4.2/benchmarks/copr-0.4.2/report.md) records exact builds and results. Real Wakterm mux-restart qualification remains outstanding.
