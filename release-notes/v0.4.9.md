# Wsh 0.4.9

A `git add` or `git commit` typed right after a prompt no longer fails with `index.lock: File exists`. Since 0.4.7, built-in prompts refresh a repository's index in the background after a slow `git status`, and in 0.4.8 that refresh held Git's index lock while Git rehashed files. The refresh now works on a private copy and takes the lock only for the moment it installs the result. With Git 2.98 or later, the prompt's own status saves its refresh and no background refresh runs.

## Changes

- Git prompt: the background refresh hashes a private copy of the index and replaces the index under `index.lock` only if no one changed it meanwhile, so the lock exists only during one file copy and rename. A refresh now also follows a second batch of touched files after a fast prompt, and a status that runs past the prompt's 2-second limit. ([cea7368](https://github.com/wakamex/wsh/commit/cea7368))
- Git prompt: a refresh written in the same second as the files were touched could leave every touched file rechecked at each prompt, and the prompt then stopped trying. The refresh now starts in the next second, and a status that stays slow retries after 2 seconds, doubling up to 5 minutes. ([d0a3e96](https://github.com/wakamex/wsh/commit/d0a3e96))
- Git prompt: with Git 2.98 or later, which [takes the index lock in `git status` only to write](https://github.com/git/git/commit/d17a7db82262f77c0d4e9b8d5a56cf8d71d6eb93), the prompt's status saves its refreshed timestamps itself, so touched files are hashed once instead of twice. Older Git keeps the background refresh. A status stopped at the time limit or by a newer prompt now receives SIGTERM before SIGKILL, so Git removes any lock it holds as it exits. [THEMES.md](https://github.com/wakamex/wsh/blob/v0.4.9/THEMES.md) explains both paths. ([7e4fb88](https://github.com/wakamex/wsh/commit/7e4fb88))
- `WSH_GIT_REFRESH_LOG`, when set to a file path, records each status's duration and each refresh decision with a timestamp and process ID. ([ee21d7c](https://github.com/wakamex/wsh/commit/ee21d7c), [7e4fb88](https://github.com/wakamex/wsh/commit/7e4fb88))
- Tests and release tooling: the Zsh flock wait test allows more time on loaded machines, and a new `verify-tap` workflow installs a published version from the Homebrew tap on a clean macOS runner. ([98fe6fc](https://github.com/wakamex/wsh/commit/98fe6fc), [2929d1c](https://github.com/wakamex/wsh/commit/2929d1c))

## Installation and upgrade

Fedora 44 x86-64 users with the [COPR repository](https://copr.fedorainfracloud.org/coprs/wakamex/wsh/) enabled can update with `sudo dnf upgrade --refresh wsh`. Homebrew users update with `brew upgrade wsh`. Shells started before an upgrade keep the previous behavior until they are restarted.
