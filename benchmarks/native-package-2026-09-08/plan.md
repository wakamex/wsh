# Native RPM and account login experiment

The passing locked native build at 0f8bb8b removes activation state from shell startup. The remaining requirement is an OS-owned account shell that survives ordinary package operations and optional-component failures. The baseline is the accepted native installation with dynamically loaded Zsh modules. The smallest package candidate installs that unchanged payload under `/usr/libexec/wsh`, exposes `/usr/bin/wsh` as a symlink, registers `/usr/bin/wsh` and `/bin/wsh`, and uses RPM's own transaction mechanisms. A local-account removal guard is evaluated against real RPM rather than assumed effective. No live host accounts or shell registration change.

Use a verified Fedora 44 Cloud image in a disposable KVM guest, with enforcing SELinux, root-owned package files, distinct fresh unprivileged accounts, and independent SSH recovery through Bash. Test real PAM/TTY login, noninteractive graphical-session-style shell invocation, fresh HOME and missing/corrupt/unreadable user state, unavailable optional runtime/integration, native job control, reboot, install, upgrade, failed transactions, interrupted post-install work, downgrade, coexistence with system Zsh, and attempted removal while a local account names Wsh. Retain exact RPM metadata, image signature/checksum, guest versions/labels, account-shell fields, command logs and transcripts. A graphical-session invocation does not count as a complete GDM login.

Exercise a running old shell that loads a previously unused module and starts its optional runtime after upgrade. First use the same stable layout and compatibility contract as ordinary Zsh packaging. If actual resource replacement exposes an ABI or lifetime failure, compare linking the shipped modules into the binary through upstream's supported build configuration before considering multiple retained payload packages or any new resource-lifetime machinery. Keep external module loading supported in that counterfactual. Any module-linking change needs full upstream correctness, Wsh PTY checks, compiled dependency/size accounting, and 50 alternating trace-off startup pairs per prompt with the existing +3 ms paired p95 gate.

Allow two interventions or four hours per failed gate before auditing its premise. Package operations are correctness experiments, not timing claims. An inability to qualify an installation policy leaves a runnable local RPM prototype and the exact unresolved decision; it does not silently authorize release or a new target floor. Existing glibc 2.28 qualification remains in stage 10.

## Package permission audit

The first payload copy retained a mode-0700 root, so an actual second account could not execute the shell. Making directories traversable exposed mode-0700 module files; strace proved EACCES on the correct installation path before Zsh reported its final failed build-prefix fallback. The second failed permission intervention invalidates the premise that directory modes alone distinguish private bundles from system installations. Normalize every immutable regular file to 0644, directories to 0755, and only binary entrypoints to 0755, then repeat real account and module checks. This also removes accidental interpreter dependencies from executable sourced functions. Allow two attempts or one hour for this complete permission normalization; do not change native lookup or introduce a resource framework for a packaging-mode failure.
