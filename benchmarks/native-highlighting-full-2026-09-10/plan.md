# Complete native main-highlighter experiment

The user requests complete C ownership of the main highlighting implementation, removing the per-token interpreted interface, with correctness and performance comparisons. Baseline is commit 2d3b2d3 and unsigned development installation 70f4b5721d0b2676ef94830d75707d22a0f69d6bda82da4c953696eb16d5bd8e. The traversal-only experiment passed 287 fixtures but left the grammar in Zsh and gained 0.9–2.6%. Its narrow boundary cannot deliver the requested consolidation.

Port the pinned main highlighter's state transitions and helpers into one private C module invoked once per redraw. Use Zsh's lexer and native parameter tables, not an embedded shell implementation or callbacks to the old main parser. Preserve the upstream lifecycle and other independently configured highlighters. The original implementation remains the control. Do not select incomplete or incompatible code.

Correctness requires all 287 authoritative upstream fixtures, exact ordered composed editor regions, normal and ASan/UBSan execution, and no execution of highlighted input. Before timing, remove the old main helper functions from the candidate fixture so an accidental fallback cannot pass. Include malformed and nested input and option-sensitive paths. Record implementation coverage separately from fixture pass counts.

Measure the same four workloads and 50 alternating pairs as the traversal experiment with the corrected observer. Report medians and paired p95 changes, plus source size and eliminated interfaces. Unlike the earlier traversal-only hypothesis, a faithful complete replacement can justify adoption through consolidation with no material regression: paired median must not regress more than 5% or 0.5 ms, whichever is larger, and p95 must not regress more than the greater of 1 ms and the identical-control p95 noise. A large speedup strengthens the decision but is not required. Instrumentation and identical-control checks remain separate.

Audit the port after two corpus runs at the same failure layer. A four-hour implementation checkpoint must record remaining failures and their causes; do not relax compatibility to force completion. Any upstream defect is recorded in UPSTREAM-ZSH-BUGS.md separately. Production selection additionally requires installed and canonical floor qualification and retained evidence verification.

The temporary-string allocation audit adds a lifetime gate before accepting timing: after a 2,000-redraw warmup, another 4,000 redraws may retain at most 8 MiB. The first candidate used permanent allocation for temporary concatenations and retained 100,000 KiB across those batches. The corrected candidate uses Zsh's scoped heap and retains 0 KiB. This changes allocation lifetime only; both raw runs are retained and timing from the leaking candidate is superseded.
