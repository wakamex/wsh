# Native updates preserve file bind mounts

The native owner now updates a bind-mounted database through its existing inode when rename fails with EBUSY. Real writable and read-only file mounts reproduce the baseline failure and verify the fix. Writable updates match pinned Zsh-z, retain the mounted inode, and set mode 0600 before writing. Read-only mounts return failure without changing content. Twenty concurrent mixed native and pinned writers preserve every increment on the mounted file. Native address/undefined sanitizer tests pass both mount cases; ordinary persistence and flock tests also pass.

The fallback holds the existing database lock through the copy. It opens the destination without following symlinks, checks its type and ownership, sets permissions before truncation, handles interrupted and partial writes, and reports failures. Other rename errors remain failures. Like the reference implementation, an in-place update cannot provide rename atomicity if the process or storage fails during writing.

Tests use `unshare -Urnm` and actual mount syscalls on private fixture files. For the normal pinned-reference comparison, a private tmpfs at /proc supplies the Docker cgroup marker that selects the existing upstream fallback branch. This fixture changes container detection only; it does not replace file operations or locks. Native sanitizer cases run with the real /proc and --native-only. No host mounts or user data are changed. The exact source, test, raw results, binary digests, and baseline are retained in mount.tar.gz and mount-identity.json. Timing is deferred to installed qualification.
