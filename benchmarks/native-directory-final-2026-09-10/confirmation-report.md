# Directory database confirmation parity

Whole-database removal now uses Zsh's read builtin before acquiring the database lock. Actual controlling-PTY comparisons against pinned Zsh-z pass for approval, rejection, and Ctrl-C in normal and address/undefined sanitizer builds. Redirected input without a controlling terminal cannot approve deletion. The separate persistence regression still passes actual flock contention, recovery, and twenty mixed writers.

The baseline prototype returned failure without prompting. The first intervention prompted correctly but left read's answer in REPLY, causing the wrapper to try changing directory to y after successful deletion. Clearing REPLY fixes that interaction. Final successful and rejected PTY transcripts, exit statuses, and database bytes match the reference. Each test independently acquires the actual Zsh database lock while confirmation is waiting, proving that the prompt does not hold the lock. Only the private test database is cleared.

The test command is `python3 native/test-directory-confirmation.py BINARY MODULE_DIRECTORY FIXTURE_DIRECTORY OUTPUT`. Fixtures come from `native/prepare-directory-owner.py`. Normal tests use the baseline bundle named in plan.md. Sanitizer tests use the private instrumented installation and module identified in confirmation-identity.json, with ASAN_OPTIONS=detect_leaks=0 and UBSAN_OPTIONS=halt_on_error=1. Source inputs and raw results are retained in confirmation.tar.gz. Ordinary lookup timing was not repeated because the change only executes for recursive removal of the root entry. Installed adoption and floor qualification follow separately.
