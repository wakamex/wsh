# Global startup mismatch in the first doctor comparison

The first doctor comparison measured different effective configuration. Rust forces `-d`; the native candidate preserves global startup. Strace directly shows the native child sourcing Fedora's `/etc/zshrc` and `/etc/profile.d` programs. Median native time was 65.528 ms versus 12.211 ms for Rust, with a +55.335 ms paired p95 difference.

The next comparison will leave both implementations unchanged and put `unsetopt globalrcs` in the shared fixture's `.zshenv`. This reproduces the baseline's global-file policy without suppressing real global startup in the product. The +3 ms paired p95 threshold and 50 alternating pairs remain unchanged. Existing first-run real-OMZ behavior checks with native global startup remain retained. A separate correctness fixture will verify that native doctor actually includes a global ownership setting.

The matched global-policy comparison still failed at +7.044 ms paired p95. This is the second failed comparison, so the initial process-lifecycle premise is revised before another intervention. The trace shows the child closes its report pipe before `_exit`, and the parent observes EOF, finds the child not yet waitable, and enters a ten-millisecond polling sleep. The new hypothesis is that report closure is occurring at the wrong lifecycle boundary. Flush the bounded report but leave its descriptor open until `_exit` closes it, so EOF tracks process teardown. Keep the timeout, existing workload, 50 pairs and +3 ms gate. Allow at most two interventions or one hour on this hypothesis.

Leaving the pipe open until `_exit` still failed at +6.986 ms paired p95. Pipe teardown can precede waitable process completion inside the kernel, so closure alone cannot remove the wait. The second bounded intervention changes only the post-EOF wait interval from 10 ms to 1 ms. The normal report wait remains event-driven through `poll`, and the ten-second deadline and cleanup remain unchanged. This is smaller than introducing signal-mask coordination solely for the final child-reaping gap.

The 1 ms final wait passed at -2.103 ms paired p95. An added background-job check then exposed a separate correctness problem: using `_exit` after normal initialization skips Zsh's own job cleanup. The next causal change uses `zexit` for report completion and ownership failures, with the normal forced-exit acknowledgement already used by native shell termination. This preserves exit traps, history handling and Zsh-owned job cleanup. Re-run correctness before timing. No additional supervisor or child-discovery subsystem is proposed.
