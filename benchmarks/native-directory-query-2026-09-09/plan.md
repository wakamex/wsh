# Compare directory matching at its existing owner boundary

Start from `1ca08c5` and the pinned 1,890-line Zsh-z implementation. Its matching routine loops over database entries, checks directory/keep rules, calculates rank and applies native Zsh patterns. Most surrounding code owns persistence, privilege-sensitive paths, custom commands, completion and user options. Porting only the calculation must not claim those responsibilities have disappeared.

First retain 50 warm lookup samples for 100 and 1,000 real directory entries. The focused C candidate is a private Zsh module replacing only the matching/ranking loop, using Zsh's own pattern, case-conversion and arithmetic implementations. Keep database reading/filtering/writing, common-root selection, output and editor adapters in the unchanged reference. Compare the complete query outputs against actual Zsh-z, including rank/time/frecency, case modes, Unicode and shell metacharacters, missing and kept paths, trailing slash, ties, custom commands and data immutability. No extra helper or resident service is introduced.

Use private configurations and a fixed clock input in both variants for exact score comparisons. Run correctness and sanitized module checks before 50 alternating warm pairs at each database size. Require no more than +3 ms paired p95 regression and at least a 20% median reduction at 1,000 entries to justify an additional partial-port interface. Count C, retained Zsh and module glue honestly. A passing kernel alone does not authorize deleting the upstream component or replacing its persistence behavior. Two failed interventions or two hours at a gate require a premise audit; preserve a decision-dependent prototype if the complete ownership comparison remains unresolved.

The baseline warm lookup median is 4.701 ms at 100 entries and 44.385 ms at 1,000 entries. The candidate keeps the existing function's local variables and output helper, replaces its per-entry loop with one native builtin call, and invokes the same native pattern/case/arithmetic engines. Numeric fields are checked before entering arithmetic; file-delimiter ambiguities are not allowed to become native code execution. Any newly exposed reference defect must be recorded separately rather than silently described as parity.
