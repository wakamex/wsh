# v0.1.1 must install and reach an editable prompt within 5 seconds at p90

The `v0.1.0` public bootstrap failed before activation because the installer smoke test bypassed the bundle's relocatable Zsh startup contract. The corrected candidate changes only that invocation and strengthens its fixture. It must pass the original fresh-install experiment on the current Fedora host and inside the pinned glibc 2.28 Rocky 8.10 environment without changing the 5-second total p90 or 50 ms post-install first-prompt p90 gates.

Each environment receives one unmeasured correctness run followed by 10 measured runs. Every run creates fresh home, binary, libexec, install, and activation directories. Timing begins immediately before downloading the release-specific bootstrap from its immutable GitHub Release URL. The harness records bootstrap-fetch, bootstrap-execution, first-prompt, and complete elapsed milliseconds separately. Bootstrap execution includes the four real GitHub HTTPS asset downloads, native-tool digest checks, offline GitHub Actions provenance verification, archive validation and extraction, complete payload hashing, smoke tests, and atomic activation. The final interval launches the installed `wsh` under a PTY and ends when its first editable `% ` or `# ` prompt is observed.

Every installation must select release `v0.1.1` and the exact source commit named by its annotated tag. The environment process is already running before measurement, so container startup is excluded from the glibc 2.28 result. Network conditions are recorded but not controlled; the result describes GitHub delivery observed from this host rather than a universal download latency. A failure to download, verify, activate, identify the exact release, or reach a prompt fails the experiment rather than becoming a latency sample. No further installer intervention is admitted under this plan.
