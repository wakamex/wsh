# Compare helper overhead with native child ownership

Start from `412798d` and the complete passing C helper. The helper adds 713 KiB p90 in the existing raw-Zsh-plus-integration memory workload, while collection and startup stay within the +3 ms regression gates. Measure 1,000 sequential ping round trips after one warmup on CPU 0 to bound request parsing, response encoding and pipe exchange independently of Git. Retain raw samples and empty-clock cost; this is a component measurement, not an editor-latency claim.

The smallest in-process counterfactual loads the unchanged C collector into the actual pinned Zsh through a private test module and runs collection on a worker thread. Before wiring prompt rendering, test whether Git child ownership works alongside Zsh's existing SIGCHLD handling. Run 100 real-Git requests while Zsh continues interpreting builtins, plus a matched standalone-host control. Preserve a runnable module and every failure. No module is installed into normal Wsh. Worker state must stay alive until joined, unloading while active must fail, and all test processes have outer deadlines.

A working candidate must preserve every request, leave Zsh's independent jobs correct, and keep collection off the editor thread. Any subsequent native intervention must also preserve environment snapshots while the shell changes variables, cancellation, shell exit, foreground job control and failure containment. Allow at most two interventions or two hours at a failing ownership gate before a premise audit. Do not add a native child registry, fork handshake or signal-routing framework solely to complete the port; describe its concrete benefit and smaller alternatives first. The passing helper remains the default counterfactual. A failed ownership probe can reject this direct embedding approach without claiming that every possible native asynchronous design is impossible.
