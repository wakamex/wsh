# Preserve access when login-shell bundle selection fails

An external Fedora report reproduced `error: no active bundle state` with a fresh account whose login shell was a Wsh launcher. The original account lost GDM and TTY access after an update and reboot, but its original state was not retained here; the fresh account does not establish the original failure cause. Current launcher source ignores login argv[0] and treats raw `-c` as a manager usage error. Missing, unreadable, corrupt, unsupported-version, and unusable bundle references all terminate launcher startup.

The smallest intervention distinguishes Unix shell invocations from manager commands, preserves healthy Zsh login and command semantics, and attempts a fixed system Bash recovery shell only when bundle selection or exec fails. Recovery uses `/bin/bash --noprofile --norc`, clears startup-injection variables and Wsh integration environment, sets SHELL to system Bash, and preserves supported shell arguments as exact argv. It changes no account configuration or bundle state. It must not turn a failed command, script, manager operation, or unsupported Zsh option into a successful recovery session.

Before implementation, run the login-style regression against the current release manager and retain the failure. After implementation, require actual execve login argv[0], raw -c and -lc, healthy Zsh login startup, exact command arguments including non-UTF-8 bytes, exit status, missing state, malformed state, incompatible state, permission denial, missing bundle, changed entrypoint metadata, and an exec-time missing interpreter to pass. Recovery must ignore poisoned Bash startup files and BASH_ENV, avoid PATH/SHELL-based fallback selection, and preserve an interactive PTY with Ctrl-C, stopped-job/fg behavior, and a command prompt. Manager commands and rejected shell options must remain errors. Do not modify /etc/passwd, /etc/shells, or the live user installation.

Use the existing unsigned bundle ccf3c17708aae1b1fc23c4170d54ff6e78a919f0adc0e0950f3590c6325c9698 and preserve the current manager binary as the control. Run Rust tests and the complete host bundle suite, and include the new regression in the canonical glibc 2.28 suite. Compare 50 alternating ordinary healthy startup pairs with the same bundle and instrumentation; require p95 added latency at most 3 ms and no new child process in the normal exec chain. Record identities, raw results, commands, and limitations. Stop and audit after two failures at any intervention gate. A missing launcher, a loader failure after successful exec, a broken system Bash, PAM policy, or user startup code exiting after successful handoff remain outside this pre-exec recovery mechanism and must be documented clearly.
