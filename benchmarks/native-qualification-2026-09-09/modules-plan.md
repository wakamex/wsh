# Compare linked modules for running-shell package coherence

Start from `d2f6513`. The package currently replaces dynamic modules beneath a running shell, and Zsh's dynamic loader has no general check that their compiled internal structures match that old executable. The existing package evidence qualifies only same-ABI replacement. An exact versioned module directory would prevent accidental cross-loading but leave old shells unable to load removed modules; preserving old resources introduces retention and cleanup ownership.

Test Zsh's existing `--disable-dynamic` build mode as the smaller native counterfactual. Link the same configured bundled modules into the executable. Require the upstream suite, native startup/foreground/profile and all current component contracts to pass. A running shell must still load a previously unused bundled module after the on-disk module tree is absent or replaced. Test unload/reload, normal module discovery and ordinary startup without optional integration. This does not promise compatibility with externally built third-party C modules.

The first `--disable-dynamic` build failed the upstream multibyte suite because `zsh/stat` was unavailable, with other module cases skipped. Disabling the loader alone does not preserve the configured module set and also removes external-module loading. The next hypothesis uses Zsh's documented `config.modules` linkage values: convert the configured dynamic bundled modules to static linkage while keeping the dynamic loader enabled. The final candidate must also load an actual separately compiled module against the matching Zsh headers. Preserve the first build log and builder source as the rejected counterfactual.

After correctness, compare 50 matched startup pairs with the same C helper and the existing +3 ms paired p95 gate. Compare 20 matched private-memory samples and require no more than 4 MiB added PSS from the linked build. Record executable size and complete dependencies. Accept linked bundled modules if the compatibility and resource gates pass; otherwise retain the prototype and package-lifetime decision. Two failed interventions or two hours at a gate require a premise audit. This experiment does not authorize publication or changes to the host account shell.
