# Compare lazy history duplicate filtering

Start from `546b221`. The pinned history-substring-search plugin already delegates its initial pattern search to the native history parameter. Its remaining result loop advances through raw history indices, reads current history entries and filters duplicates lazily. Compare that loop with a private C builtin using the same native parameter tables. Keep initial matching, navigation, editor state, bindings, highlighting and plugin ownership unchanged. A stateless eager deduplication pass is unsuitable because it moves all work to the first result and snapshots entries before later navigation.

First measure the unchanged loop with 100 and 10,000 duplicate entries. Compare actual plugin results after every call, including uniqueness disabled, HIST_IGNORE_ALL_DUPS, duplicate groups, empty/multiline/metacharacter entries, exhaustion, and history changes between calls. Run compiler diagnostics and sanitizers before 50 alternating matched pairs on CPU 0. Require exact state/return parity, no more than +1 ms paired p95 regression, and a 20% median reduction for the 10,000-duplicate scan to justify a partial-port interface. Keep the complete plugin and interface costs visible. Stop after two failing interventions or two hours at a gate and retain a decision-dependent prototype if editor qualification remains unresolved.
