# Five native component experiments

History navigation and completion scanning pass their declared performance gates. Directory ownership fails persistence compatibility, the larger autosuggestion port misses its whole-sequence improvement gate, and highlighting attribution points to the parser loop rather than another small helper. All candidates remain disabled; the reports distinguish passing experimental boundaries from complete feature ownership and installed integration.

| Component | Result | Retained decision |
| --- | --- | --- |
| [Directory jumping](directory-report.md) | 720 query comparisons pass; mutation/configuration differences remain | Finish database compatibility before considering selection |
| [History substring search](history-report.md) | Default 10,000-entry sequence improves 11.0%; unique duplicate-heavy sequence improves 73.1% | Strong candidate; decide and qualify the remaining editor/highlight ownership boundary |
| [Autosuggestions](suggestion-report.md) | Large-history editing and acceptance improves 14.4%, below the 20% gate | Keep disabled; async and registration adapters still prevent complete ownership |
| [Completion initialization](completion-report.md) | Full native scan passes all cache/startup/first-Tab gates; header-only intervention fails | Strong candidate; bind to bundled compinit and qualify the installed integration before selection |
| [Syntax highlighting](highlight-report.md) | Main parser loop costs about 40%; style fallback about 13% | A substantial parser port requires a separate decision; small helper ports cannot meet the fixed gate alone |

The experiments extend the earlier kernels with runnable code, authoritative comparisons, actual ZLE tests, sanitizer coverage where C changed, and retained raw measurements. They do not complete the three entire C feature ports: directory persistence, history editor/highlight ownership, and autosuggestion async/registration ownership remain open. The native registration scanner also needs installation integration. These boundaries are explicit so passing subset measurements cannot be mistaken for a finished replacement.

The source/build context is in `identity.json`; per-component commands, source snapshots, configurations, transcripts and raw results are retained beside these reports or in the named result archives. `SHA256SUMS` and the shared evidence verifier bind the claims to those inputs. Every measured installation is an unsigned development artifact. The existing selected native installation and published release were not changed by these experiments.
