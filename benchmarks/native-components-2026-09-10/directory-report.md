# Directory data ownership remains a disabled prototype

The complete C data/query candidate matches all 720 query comparisons with the pinned plugin, but it does not yet preserve the database contract. Ten mutation/configuration comparisons found five byte-level differences, including duplicate records and exclusion of the home directory when added as `.`. Keep the existing implementation selected. No new performance claim is justified before those correctness failures are resolved.

The candidate owns file reading, query/ranking, POSIX record locking, temporary-file replacement and add/remove operations. A generated private fixture retains the pinned plugin's editor, registration and unload adapters. It is not connected to Wsh's build or startup. Root-recursive removal deliberately refuses pending confirmation parity. Privileged owner handling, lock interoperability/concurrent writers, bind-mounted database replacement and the full editor/unload matrix remain unqualified.

The query corpus covers case, trailing slash, uncommon matching, missing-directory retention, rank/time/list/completion modes and shell-special path bytes. Normal and AddressSanitizer/UndefinedBehaviorSanitizer runs agree. Mutation comparisons retain exact output and database bytes; numeric formatting and record order are included in the reported byte differences, so five differences do not imply five independently demonstrated data-loss bugs. Duplicate records remain duplicated in the candidate, and relative home exclusion differs behaviorally. The earlier common-root and substitution failures are retained with the audit. The last correction also copies the selected parameter before replacing it, avoiding use after parameter replacement.

The next decision is whether to finish the complete owner with those compatibility obligations or retain the already measured query kernel. The current result supports further bounded work, not selecting this candidate. No writes/startup benchmark was run after the failed persistence gate.
