# Deferred native completion experiment

Eager native completion fixed missing Git branch and directory-jump completion, but exceeded the startup budgets. Test whether initializing on the first Tab preserves startup speed while meeting the same 100 ms first-Tab budget. The smallest prototype binds a private completion widget only when native completion and a custom Tab binding are absent. The widget runs ordinary bundled `compinit -i`, registers Wsh-owned directory jumping, restores the native Tab binding, refreshes Wsh-owned autosuggestion bindings, and invokes native completion. No startup background work, audit bypass, generated index, daemon, or production change is part of this experiment.

Compare no initialization, eager initialization with missing/reusable dumps, and deferred initialization with missing/reusable dumps. Use the same manager at source 950bde517bdbb75d3c2a0933293b95f3d013a967 and unsigned development bundle ccf3c17708aae1b1fc23c4170d54ff6e78a919f0adc0e0950f3590c6325c9698 as the previous experiment. Record binary and complete manifest identities. Use private startup files, all three Wsh editing defaults, Wsh-owned directory jumping, an empty WSH_THEME, and a small real Git repository. Native audit stays enabled. Cold denotes a missing compdump, not flushed operating-system caches.

Before timing, exercise actual ZLE Git branch completion, spaced paths, z as the first completion, repeated completion, autosuggestion display/acceptance and history search after initialization, highlighting, an unrelated custom widget, and preservation of preexisting native completion and a custom Tab binding. Cover emacs and vi insert Tab bindings. Keep every correctness result and transcript, including failures. A failed prototype must be diagnosed before timing; at most one local correction is allowed under this hypothesis.

After correctness, run 50 fixed rounds of all five variants, reversing order on alternate rounds. Measure startup through native OSC 133 B, first Git-branch Tab through a buffer-capture widget, and a second identical completion in the same shell. Keep the same observer and workload in every variant, with tracing off. Record all 250 samples, nearest-rank median and p95, and host observations. Do not overlap timing with local builds, tests, evidence verification, or other tool-shell commands.

Accept the deferred hypothesis only if startup p95 adds at most 20 ms versus no initialization in both cache states, and first and second Git-branch Tab p95 each stay within 100 ms in both states. Retain the eager comparison's existing 20 ms cached and 100 ms missing-cache startup budgets. Stop after one completed timing matrix, regardless of outcome. Do not substitute the second-Tab result for first-use latency or retry a failed budget. A failure leaves completion defaults unchanged and identifies the next hypothesis without implementing it.
