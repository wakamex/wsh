# Compiled version labels distinguish development and release builds

`wsh --wsh-version` now prints `unsigned development artifact` for development builds and `release build` for release-mode builds. The existing statement that installed resources are unverified remains. This is a Wsh build/diagnostic correction; the label does not authenticate a release or inspect mutable user state.

The existing build-header generator validates `WSH_BUNDLE_STATUS`, defaults to development, and includes the selected label in the compiled identity and build-cache digest. A development executable cannot silently satisfy a release-mode cache lookup. Runtime environment variables cannot change the compiled label. The native C source lock was refreshed, and the historical Git-recognition verifier retains its original source-lock hash through commit `4a94e99`.

`tests/native-build-status.py` generates both headers through the production builder and compiles the actual C dispatcher with strict compiler diagnostics. Host and glibc 2.28 runs pass both labels, default behavior, invalid build modes, distinct cache identities, runtime overrides, help/error handling and preservation of ordinary Zsh options. A fresh native development installation also passes version output, missing-resource relocation, corrupt metadata, user-startup isolation, help, upstream `--version`, ordinary script arguments and native command execution. The fresh host build passed the upstream Zsh suite and installation inventory verification.

The test is part of the complete retained-evidence entrypoint, and the canonical build additionally supplies its freshly built installation. CI explicitly installs the C compiler needed by the dispatcher test. The migration harness derives its expected label from the input installation's build status instead of assuming every package is a development build.

`version-status.json` records source and installed binary identities; `version-status.tar.gz` retains the build log, manifest, native lock, version output and host/floor regression results. The artifact is an unsigned development build. Release-mode coverage compiles the production dispatcher/header on both targets; a complete release-mode RPM and the final two-build package comparison remain part of release qualification. Ordinary startup and editor code paths were not changed, so timing benchmarks were not repeated.
