# Compare syntax-highlighter command classification

Start from `caceaaa`. The main highlighter already uses native Zsh token splitting and parameter tables. Compare its command-classification branch with a private C builtin using those same tables. Keep token interpretation, styles, layered spans, cache ownership, unknown-command fallback and editor lifecycle in the reference. This is a focused native comparison, not a claim that a command classifier replaces the full syntax highlighter.

Use the actual upstream main-highlighter suite plus direct cases for regular/global/suffix aliases, reserved words, functions, builtins, commands, cache behavior and shell-metacharacter names. Run diagnostics and sanitizers before timing. Measure complete main-highlighter calls, with the same buffers and instrumentation, in 50 alternating pairs on CPU 0. Require exact highlight-span parity, no more than +1 ms paired p95 regression, and at least 20% median reduction on a 100-command buffer to justify the added interface. The smallest counterfactual is its existing command cache, cleared by its precmd hook; retain that in both variants and include repeated-command and distinct-command buffers with cold and reusable cache state. Stop after two failed interventions or two hours at a gate. Keep the selected baseline if the focused kernel does not simplify the complete component enough for adoption.
