# Native RPM prototype

This is a local Fedora packaging and login test slice. It installs the verified native development payload under `/usr/libexec/wsh` and exposes the account-shell path `/usr/bin/wsh`. The RPM owns registration of `/usr/bin/wsh` and `/bin/wsh` in `/etc/shells`. Immutable directories are 0755, data and modules are 0644, and executable entrypoints are 0755. The package includes the current Rust runtime and development provenance. It is unsigned and is not a published installation method.

Build with `python3 packaging/build-rpm.py <native-installation> <rpm-output-directory>`. The input must be a verified native development payload. `--release` and `--fault` support the disposable VM transaction experiment; fault injection belongs to this prototype. Install the resulting RPM only in an isolated test machine with an independent working recovery account. Package updates use DNF or RPM. There is no native self-update or activation step.

The [retained Fedora test](../benchmarks/native-package-2026-09-08/report.md) covers actual PAM/TTY login, authenticated unprivileged `chsh`, SELinux enforcing with both unconfined and confined accounts, reboot, unavailable optional components, and package transactions. It includes a running old shell loading a module and starting the replaced runtime after a same-ABI upgrade. Public release qualification still needs a resource-lifetime policy for incompatible Zsh ABI changes, a decision on supported account-directory/removal policy, and stage 10's target-floor, reproducibility, and migration tests.

Ordinary removal refuses while `/etc/passwd` contains a local account using either registered Wsh path. Change those accounts to another installed shell first. This guard does not enumerate remote identity services or follow arbitrary shell aliases. Administrators can bypass RPM scriptlets, remove files, or remove required system libraries; the test confirms that `rpm --noscripts` bypasses the guard. Wsh cannot run after its account-shell executable disappears.

`vm.py` runs guest scripts through the independent recovery account and retains input and output. `test-login.py` uses the guest's actual serial getty and PAM. `test-vm-recovery.py` changes only guest state and optional resources and restores package files after each case. The guest transaction and `chsh` tests run inside that isolated VM. The evidence archive contains the VM command, verified image identity, seed configuration with a public test key, package metadata, and exact test source. No private SSH key is retained in the repository.
