# Native RPM distribution

The [COPR repository](https://copr.fedorainfracloud.org/coprs/wakamex/wsh/) provides Fedora 44 and 45 x86-64 packages and DNF updates. For a distro build from source or an authorized COPR update, use [the source RPM recipe](SOURCE-RPM.md). It declares build dependencies, compiles all native product code offline and runs the shared correctness suite. The payload-packaging procedure below remains the separate canonical GitHub artifact path and transaction-fixture builder.

This directory builds the Fedora native package and tests login and package transactions. It installs `/usr/bin/wsh`, the private helper under `/usr/libexec/wsh`, and data under `/usr/share/wsh`. The RPM owns registration of `/usr/bin/wsh` and `/bin/wsh` in `/etc/shells`. Immutable directories are 0755, data and modules are 0644, and executable entrypoints are 0755. The package includes the selected C runtime and development provenance. Local artifacts are unsigned development builds. Official releases are available on GitHub.

Build with `python3 packaging/build-rpm.py <native-installation> <rpm-output-directory>`. The input must be a verified native installation. Fault injection is allowed only for development payloads. `--epoch` fixes artifact timestamps (default: current source commit time). Packaging normalizes archive ownership/modes, gzip headers and RPM build host/time; reproducibility requires the same payload, epoch, RPM tools and macros. `--release` and `--fault` support the disposable VM transaction experiment; fault injection belongs to this prototype. Install the resulting RPM only in an isolated test machine with an independent working recovery account. Package updates use DNF or RPM. There is no native self-update or activation step.

The [retained Fedora test](https://github.com/wakamex/wsh/blob/c7af8c63bcecb7d276ab6ae92896b0e5f90a66c3/benchmarks/native-package-2026-09-08/report.md) covers actual PAM/TTY login, authenticated unprivileged `chsh`, SELinux enforcing with both unconfined and confined accounts, reboot, unavailable optional components, and package transactions. It includes a running old shell loading a module and starting the replaced runtime after a same-ABI upgrade. The [final C payload qualification](https://github.com/wakamex/wsh/blob/c7af8c63bcecb7d276ab6ae92896b0e5f90a66c3/benchmarks/native-qualification-2026-09-09/package-report.md) repeats these tests and establishes identical source archives and RPMs from separate packaging directories. Bundled modules are now linked into each shell; incompatible external modules, autoload functions and helper protocols still need their normal release compatibility policy. The package is named `wsh`. See [installation instructions](../NATIVE-INSTALLATION.md).

Change account shells before removing Wsh. Following Fedora Zsh, uninstall removes the registered paths from `/etc/shells` and leaves account records unchanged. Package transactions do not veto removal based on `/etc/passwd`.

`qualification-vm.zsh create RELEASE WORK` builds a disposable Fedora qualification VM from that release's Fedora Cloud Base image, after checking the image's SHA-256 against the `CHECKSUM` file and that file's signature against the release key in `/etc/pki/rpm-gpg`. Its cloud-init seed creates the passwordless-sudo `recovery` account with a fresh SSH key, the `shellempty` test account with the password the login and `chsh` tests type, a pinned SSH host key so `vm.py` runs in batch mode, the serial getty, `git-core`, `jq` and `python3`, and enables the `wakamex/wsh` COPR repository. `qualification-vm.zsh start WORK` boots it as the user unit `wsh-fedora-compliance-vm` and waits for cloud-init; only one VM runs at a time, since every tool reaches it on `127.0.0.1:22284`. `test-hosted-rpm.py VERSION-RELEASE SOURCE_REVISION` checks an installed package's layout, licenses, bundled declarations, shell registration, version and source identity as root in the guest. `vm.py` runs guest scripts through the independent recovery account and retains input and output. `test-login.py` uses the guest's actual serial getty and PAM. `test-vm-recovery.py` changes only guest state and optional resources and restores package files after each case. The guest transaction and `chsh` tests run inside that isolated VM. The evidence archive contains the VM command, verified image identity, seed configuration with a public test key, package metadata, and exact test source. No private SSH key is retained in the repository.
